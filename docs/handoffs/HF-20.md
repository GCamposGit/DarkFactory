## 2. Objetivo, Escopo e Não-Objetivos

### Objetivo
Capacitar a Dark Factory a criar e manter produtos reais a partir de blueprints padronizados por arquétipo, validando o motor com um target real em produção (**ATRIUM** — `Site_ggcampos`, portfólio executivo publicado em `ggcampos.com` via Hostinger FTP e DNS Cloudflare).

### Escopo Entregue
1. **Subsistema Canônico de Arquétipos (`core/archetypes/`)**:
   - `models.py`: Contratos tipados em Pydantic v2 (`ArchetypeKind`, `ArchetypeManifest`, `StackDescriptor`, `ContentSchemaDescriptor`, `ScaffoldRequest`, `ScaffoldResult`).
   - `registry.py`: Catálogo centralizado com os 3 arquétipos previstos no roadmap (`personal_presence`, `internal_tool`, `second_brain`).
   - `scaffolder.py`: Motor de geração *one-shot* automatizado, desacoplando o motor estrutural (Astro 5 + Tailwind 4 + Layouts + SEO) da camada de dados de conteúdo.
   - `cli.py`: Interface de linha de comando (`list`, `inspect`, `init`).
2. **Arquétipo de Presença Digital (`personal_presence`)**:
   - Stack: Astro 5 SSG, Tailwind CSS 4 (`@tailwindcss/vite`), MDX, TypeScript.
   - Schemas de conteúdo tipados via Zod: `cases` (com métricas quantificadas e confidencialidade) e `thinking` (ensaios/blog).
   - SEO out-of-the-box: sitemap XML automático, OpenGraph tags dinâmicas, canonical links, rota 404 e Colophon.
   - Esteira de validação integrada (`npm.cmd run build` + `node scripts/verify_build.mjs`).
   - Pipeline de deploy automatizado via GitHub Actions para Hostinger FTP (`SamKirkland/FTP-Deploy-Action@v4.3.5`).
3. **Adoção Brownfield do `Site_ggcampos` via Skill 07 (`Project Adoption Gateway`)**:
   - Repositório clonado e inspecionado transacionalmente em `C:\dev\Site_ggcampos`.
   - Worktree de adoção criada em `C:\dev\Site_ggcampos_worktrees\codex-darkfac-adoption`.
   - Runtime isolado namespaced instalado em `.factory/runtime/` com proveniência auditável (`.factory/darkfac.lock.json` com 213 arquivos verificados e sem drift).
   - Governança alinhada à `PROJECT_BIBLE.md` do Atrium em `MISSION.md` e `FACTORY_RULES.md`.
   - Harness configurado e validado emitindo `[STEP_PASS] astro_build`, `[STEP_PASS] routes_verification` e `[HARNESS_PASS]`.
4. **Desacoplamento e Integrações Futuras**:
   - O gerador *one-shot* isola o conteúdo em arquivos Markdown/MDX, pronto para injeção via **Skill 15** (`anti-slop-content-engine`) e conexão direta com a base de conhecimento do **HF-22** (`Segundo Cérebro`).

### Não-Objetivos
- Não alterar as credenciais reais de FTP nem substituir o conteúdo autoral em produção do site `ggcampos.com`.
- Não impor frameworks de backend dinâmico ou banco de dados a sites de presença que devem permanecer 100% estáticos (SSG).
