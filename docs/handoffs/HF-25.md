## 2. Decisões do Grill (Alinhamento Estruturado)

1. **Guarda-Costas Inviolável Anti-Autoalteração do Verificador (Fail-Closed)**:
   - Propostas de evolução são sumariamente rejeitadas com erro de violação de segurança (`SecurityViolationError`) se tocarem em:
     - Verificadores ativos: `core/harness/`, `harness.config.json`, `core/orchestrator/guard.py`, `core/acceptance/`, `core/workflow/verification.py`, `core/workflow/readiness.py`.
     - Arquivos protegidos de governança: `MISSION.md`, `FACTORY_RULES.md`, `FACTORY_GOVERNANCE.md`.
2. **Avaliação em Sandbox Isolada (Holdout Sandbox)**:
   - Toda proposta é testada em ambiente temporário isolado (`EvolutionHoldoutSandbox`), sem contaminar o repositório principal ativo.
   - Avalia compilação, sintaxe e executa suítes holdout designadas antes de autorizar qualquer promoção.
3. **Promoção Controlada com Snapshot de Rollback Atômico**:
   - A promoção de candidatos aprovados captura deterministicamente o snapshot do estado anterior do arquivo em `.factory/evolution/rollbacks/` antes da escrita.
   - Em caso de qualquer regressão detectada em produção, o comando `rollback` reverte o arquivo original instantaneamente.
   - Alterações em `.agents/skills/` disparam automaticamente `scripts/sync_skills.py` para preservar paridade com `.claude/skills/`.
4. **Catálogo Centralizado de Componentes Cross-Projeto**:
   - Catálogo durável em `.factory/catalog/components.json` gerenciando blocos reutilizáveis entre os projetos registrados (`darkfac`, `site-ggcampos` / Atrium, `segundo-cerebro`, `jarvis`).
   - 5 componentes essenciais pré-carregados (`atrium-seo-validator`, `atrium-anti-slop-linter`, `second-brain-mcp-connector`, `portfolio-budget-guard`, `ftp-deploy-pipeline`).
   - Funções para empacotar/exportar novos componentes a partir de qualquer projeto e sincronizá-los para outros com checagem de integridade SHA-256.

## 3. Escopo Entregue

1. **Subsistema de Auto-Evolução (`core/evolution/`)**:
   - `models.py`: Contratos Pydantic v2 (`EvolutionProposal`, `HoldoutEvaluationResult`, `RollbackSnapshot`, `EvolutionReport`, `EvolutionTrigger`, `EvolutionTarget`, `EvolutionStatus`, `SecurityViolationError`).
   - `sandbox.py`: `EvolutionHoldoutSandbox` com auditoria de fronteiras fail-closed e isolamento em diretório temporário.
   - `engine.py`: `FactoryEvolutionEngine` com fluxo `propose` -> `evaluate` -> `promote` -> `rollback` e sincronização de skills.
   - `cli.py`: Interface de linha de comando (`status`, `propose`, `evaluate`, `promote`, `rollback`).
2. **Subsistema de Catálogo Cross-Projeto (`core/catalog/`)**:
   - `models.py`: Contratos Pydantic v2 (`ComponentDescriptor`, `ComponentFile`, `ComponentKind`, `SyncResult`).
   - `manager.py`: `CrossProjectCatalogManager` com 5 componentes built-in, exportação atômica e injeção sincronizada nos projetos.
   - `cli.py`: Interface de linha de comando (`list`, `inspect`, `export`, `sync`).
3. **Integração com o DarkHub**:
   - Endpoints REST em `hub/backend/api.py`: `/api/evolution/*` e `/api/catalog/*`.
   - Visualização e atualização dinâmica em `hub/frontend/catalog.js` montada no dashboard principal.
4. **Suítes de Testes Automatizados**:
   - `tests/test_factory_evolution.py`: Cobertura de propostas, auditoria de segurança (tentativas de adulteração bloqueadas), sandbox, promoção e rollback.
   - `tests/test_cross_project_catalog.py`: Cobertura de registro, exportação de projetos, sincronização com integridade de hashes e compatibilidade.
