# HF-27-07 — Deploy + smoke + rollback por target

Papel: economy · Depende de: HF-27-01, HF-27-06 · Resolve: D1 (etapas terminais mock).

## Objetivo
Publicar o SHA mergeado no alvo do projeto, provar que está no ar com checks de smoke e reverter sozinho se falhar.

## `core/line/stage_release.py`
Reusa `core/orchestrator/deployment_adapter.py` (`DeploymentAdapter`, `DokployDeploymentAdapter`, `LocalServiceDeploymentAdapter`, `execute_deployment_with_safeguards`) e adiciona:

- **`FtpMirrorDeploymentAdapter`** (Hostinger/ATRIUM): `commands.build` → envia o diretório de saída (`deploy.params.dist_dir`) por `lftp mirror -R --delete` (ou `ftplib` puro, se o lftp não existir) para `releases/<sha>/` e troca o symlink ou pasta `current`. Se o host não suportar symlink, faz upload para `public_html` e guarda o **SHA anterior em `.darkfac-release`** para rollback por novo deploy do SHA anterior. A credencial vem de secret ref (env).
- **Deploy:** `deploy(project, merge_sha)`. `dokploy`: webhook + polling até o status do deploy terminar, ou até o endpoint de versão/health responder o novo SHA. `local_service`: exige capability `target:local_service` (roda no Desktop) e executa `deploy.params.restart_cmd`. `none`: pula para smoke/local.
- **Smoke:** para cada `SmokeCheck` do projeto + `tickets[*].smoke`: GET com retry (5x, 10 s), `expect_status` e `expect_text`. Se o projeto expõe `/version` ou `/healthz` com SHA, confere o SHA. Opcional: se o planner gerou `smoke.spec.ts` e o host tem Playwright, roda headless.
- **Rollback automático:** se o smoke falhar, redeploy do SHA anterior (`last_good_sha` gravado no control store ou em `.darkfac-release`), smoke do anterior e `retry` para `development` com o log do smoke (iteração nova "corrigir regressão em produção"). Duas falhas de smoke seguidas para o mesmo run → `failed(prod_smoke_failed)` + notificação.
- `requires_commercial_acceptance`: antes do deploy, `waiting_human(kind=commercial_acceptance)` com o link do PR e o preview. Só para projetos marcados assim.
- `output_refs=[deploy_operation_id, smoke_report_ref]`. Grava `last_good_sha`.

## Aceite
- Adapter falso: sucesso grava `last_good_sha`, e smoke falho executa rollback para o SHA anterior e devolve `retry` com log.
- FTP contra servidor FTP local de teste (`pyftpdlib`, só dev) ou mock de `ftplib`: arquivos enviados e `.darkfac-release` atualizado.
- Um job `local_service` sem a capability no worker nunca é claimado (teste de `claim` com `required_capabilities`).
