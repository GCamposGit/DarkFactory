# HF-27-02 — Workspace Git por run

Papel: economy · Depende de: HF-27-01 · Resolve: D3 (cwd), D4 (base), D6 (estado em memória).

## Objetivo
Criar uma camada única e idempotente que prepara o diretório onde o agente trabalha e que transporta o estado entre etapas e hosts pela própria branch.

## API (`core/line/workspace.py`, novo)
```python
class RunWorkspace(BaseModel):
    project_id: str; run_id: str; branch: str; path: Path; base_sha: str

def workspace_root() -> Path            # env DARKFAC_WORKSPACES, default ~/.darkfac/workspaces
def checkout(project, run_id) -> RunWorkspace
    # mirror: git clone --filter=blob:none <repo_url> <root>/<project>/.mirror (1x), fetch --prune
    # worktree: <root>/<project>/runs/<run_id>, branch df/<run_id>
    # se origin/df/<run_id> existe: reset --hard nele (continua trabalho de outro host); senão cria de origin/<default_branch>
def context_dir(ws) -> Path             # <ws>/.darkfac/runs/<run_id>/
def write_context(ws, name, content)    # grava arquivo de contexto (DEMAND.md, SPEC.md, tickets.json...)
def commit(ws, message, job_key) -> str # git add -A; commit com trailer "DarkFac-Job: <job_key>"; retorna SHA; no-op se sem diff
def push(ws) -> None                    # push -u origin df/<run_id>, com retry 3x

```
- Autenticação Git: usa o que o host já tem (credencial do `gh`, ou `GITHUB_TOKEN` via `http.extraheader`), sem gravar token em disco no repo.
- O `.darkfac/runs/` **é versionado na branch**, mas removido no squash-merge por um passo de HF-27-06 (`git rm -r .darkfac/runs/<run_id>` antes do merge), com cópia do `REPORT.md` no corpo do PR. Assim o `main` fica limpo e o histórico fica no PR.

## Aceite (testes com repo bare local como "origin")
- `checkout` em host A, commit + push, e `checkout` em host B (outro root) mostram o mesmo SHA e contexto.
- `commit` repetido com o mesmo `job_key` e sem diff não cria commit novo. `find_commit_by_job` o encontra.
- Paths com espaço e Windows/POSIX funcionam (`pathlib`, `subprocess` com lista de args).
