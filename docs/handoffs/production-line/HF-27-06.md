# HF-27-06 — Integração GitHub via `gh`

Papel: economy · Depende de: HF-27-02 · Resolve: D4.

## Objetivo
Transformar a branch revisada em merge no `default_branch`, de forma idempotente, usando o `gh` CLI (já autenticado no host). `GitHubClient` e `delivery_executor` continuam como leitores/reconciliadores.

## `core/line/stage_integration.py`
1. `checkout`. Faz `git fetch origin <default>` e tenta `rebase origin/<default>`.
   - Se houver conflito: `rebase --abort` e agente em modo **write** com o prompt "resolva o merge de origin/<default> nesta branch preservando ambos os comportamentos". Depois valida (`commands.validate`). Falhou → `retry` para `development` com o log. Máximo de 1 tentativa de resolução por run antes de `failed(merge_conflict)`.
   - Push com `--force-with-lease`, só na branch `df/*`.
2. Remove `.darkfac/runs/<run_id>/` da branch num commit final (o conteúdo vai para o corpo do PR).
3. PR idempotente: `gh pr list --head df/<run_id> --json number,url,state`. Se não existir, `gh pr create --base <default> --title "<demanda curta>" --body-file REPORT_PR.md`. O corpo leva SPEC resumida, tickets, premissas do Grill, review e o comando de validação com resultado.
4. CI: `gh pr checks <n> --watch --fail-fast` com timeout de 30 min, em janelas de 5 min (retorna `retry` com `not_before` para não segurar lease por 30 min). Se o repo não tiver checks, a validação limpa do HF-27-05 é o gate.
5. Checks vermelhos: baixa o log do job falho (`gh run view --log-failed`, truncado) e devolve `retry` para `development` com esse log.
6. Merge: `gh pr merge <n> --squash --delete-branch`. Se a branch protegida exigir review humano, tenta `--auto`. Se continuar bloqueado, vira `HumanRequest(kind=repo_setting)` com o passo a passo de branch protection. Isso é configuração, não aprovação por ticket.
7. Confirma que `origin/<default>` contém o SHA do merge (regra 11 do FACTORY_RULES). `output_refs=[pr_url, merge_sha]`.

## Aceite
- Com `gh` falso (script que registra chamadas e responde JSON fixo): um PR existente não é recriado, e o merge só acontece com checks verdes.
- Um conflito simulado chama o agente de resolução 1x e depois `failed(merge_conflict)`.
- Check vermelho retorna `retry` com o log incluído no contexto do próximo development.
