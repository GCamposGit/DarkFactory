# HF-27-01 — Registry de projetos executável

Papel: economy · Depende de: — · Resolve: D5.

## Objetivo
Qualquer host (VPS ou on-prem) deve saber, só a partir do registry, **clonar, preparar, validar, buildar, publicar e verificar** cada projeto, sem path do Windows.

## Mudanças
1. `core/projects/models.py`: estender `ProjectDescriptor` com campos opcionais, retrocompatíveis e com `extra` inalterado:
   ```python
   repo_url: str | None            # https://github.com/<owner>/<repo>.git
   default_branch: str = "main"
   commands: ProjectCommands        # setup, validate, build, smoke (listas de str; vazias = autodetect)
   deploy: DeployConfig | None      # type: dokploy|hostinger_ftp|local_service|none; params: dict (sem segredo, só secret_ref)
   smoke: list[SmokeCheck] = []     # {url, expect_status=200, expect_text=None}
   exec_affinity: list[str] = []    # capabilities extras exigidas (ex.: "target:local_service", "gpu")
   requires_commercial_acceptance: bool = False
   ```
2. `core/projects/detect.py` (novo) — `detect_commands(repo_dir: Path) -> ProjectCommands`, puro e sem rede:
   - `package.json`: `npm ci` / `npm test` (se o script `test` existir) / `npm run build` (se `build` existir). Detecta pnpm/yarn pelo lockfile.
   - `pyproject.toml` / `requirements.txt`: `python -m pip install -r …` / `python -m pytest -q` / sem build.
   - `harness.config.json` (projetos DarkFac-adotados): `python core/harness/runner.py --quick`.
   - Sem teste detectado: `validate=[]`. A etapa de build então exige que o agente crie um teste mínimo (HF-27-05).
3. `core/projects/registry.py`: `resolve_commands(project, repo_dir)` combina o que está explícito com o que foi detectado (explícito vence).
4. `.factory/projects.json`: preencher `repo_url`, `deploy` e `smoke` dos 4 projetos. A fábrica deve **descobrir sozinha**: `git -C <path> remote get-url origin`, o domínio já presente e o `deploy_target` atual.

## Aceite
- Os 4 projetos carregam no modelo novo, e o JSON antigo, sem os campos, continua válido.
- `detect_commands` com fixtures node, python e harness retorna os comandos esperados. Um repo vazio retorna listas vazias.
- Nenhum segredo no JSON (validador rejeita chaves `password|token|secret` em `deploy.params` que não terminem em `_ref`).
