## 2. Decisões do Grill (Alinhamento Estruturado)

1. **Fila com Justiça Ponderada (Weighted Fairness)**:
   - Priorização proporcional favorecendo projetos de produção e receita: `atrium: 3.0` > `jarvis: 2.0` > `darkfac: 1.0`.
   - Proteção ativa contra inanição (`starvation_guard`): se um projeto de menor peso aguardar mais de `max_starvation_ticks` (padrão 5 ciclos), ele ganha prioridade determinística imediata de despacho, prevenindo congelamento.
2. **Dimensionamento Híbrido de Slots de Execução**:
   - Concorrência rigorosamente delimitada: **1 slot pesado** (`HEAVY`, GPU Ollama / suites completas de testes) e até **4 slots leves** (`LIGHT`, subagentes rápidos, lints, I/O, pesquisas de rede).
3. **Roteamento de Modelos Paid-Account-First**:
   - Prioridade 1: Consumir sempre as contas pagas diretas com saldo ativo (Gemini 3.8 Flash para pesquisa e contexto massivo; Grok 4.6 para web e documentação viva; Luna xhigh / OpenAI / Claude Code (opus-5.1) para arquitetura e codificação complexa).
   - Prioridade 2: Caso as contas diretas estejam sem saldo, rotear para o OpenRouter priorizando modelos de fronteira de alto custo-benefício (DeepSeek-V3, Qwen-2.5-Coder).
   > Correção registrada em 2026-09-20: a lista de Prioridade 1 foi alinhada ao mapa normativo de alta inteligência por harness já estabelecido em HF-07 (Claude Code / opus-5.1 como harness pago de arquitetura/planejamento), que existia quando este handoff foi escrito mas não havia sido refletido aqui.
   - Prioridade 3: Fallback automático e fail-closed para Ollama local ($0) para microtarefas ou quando a cota do projeto for atingida.
4. **Tetos Orçamentários Mensais por Projeto**:
   - Limites mensais em USD isolados por projeto (padrões: Atrium \$25, Jarvis \$35, DarkFac \$50).
   - Alerta preventivo no Telegram ao atingir 80% do teto mensal.
   - Corte imediato e fail-closed para modelos locais $0 (`LOCAL_ONLY`) ao bater 100%, impedindo estouro orçamentário.

## 3. Escopo Entregue

1. **Contratos e Modelos Tipados (`core/portfolio/models.py`)**:
   - `JobSlotKind`: enum `HEAVY` vs `LIGHT`.
   - `SlotAllocation` & `SlotCapacityConfig`: concessão e limites de slots.
   - `ProjectWeightConfig`: pesos ponderados e limiar de inanição.
   - `ProjectBudgetConfig` & `BudgetStatus`: tetos mensais, gastos acumulados e status (`ACTIVE`, `WARNING`, `LOCAL_ONLY`).
   - `RoutingPolicyResult`: modelo de decisão de roteamento com justificativa e tier (`PAID_DIRECT`, `OPENROUTER_FRONTIER`, `LOCAL_ZERO`).
   - `PortfolioEfficiencyReport`: relatório consolidado de capacidade e filas.
2. **Escalonador de Fila e Slots (`core/portfolio/scheduler.py`)**:
   - `PortfolioScheduler`: implementação durável de Weighted Deficit Round-Robin e starvation guard.
   - Gerenciamento atômico de alocações de slots pesados e leves com expiração e liberação automática.
3. **Gerenciador de Orçamentos e Alertas (`core/portfolio/budget_manager.py`)**:
   - `PortfolioBudgetManager`: persistência durável em `.factory/portfolio/budgets.json`.
   - Avaliação contínua de limiares (80% warning e 100% cutoff).
   - Integração com `TelegramGateway` para notificações imediatas ao Owner.
4. **Roteador Otimizado de Modelos (`core/portfolio/router_optimizer.py`)**:
   - `PortfolioModelRouter`: hierarquia estrita Paid-First -> OpenRouter -> Local-$0.
   - Consulta a saldos de contas via `ApiCreditsMonitor` e corte preventivo para `LOCAL_ONLY`.
5. **Interface CLI Headless (`core/portfolio/cli.py`)**:
   - Comandos: `status`, `set-budget`, `record-spend`, `route-task`, `enqueue-job`, `dequeue-job`.
6. **Suíte de Testes Automatizados (`tests/test_portfolio_efficiency.py`)**:
   - 8 testes cobrindo capacidade de slots, WFQ, inanição, orçamentos, roteamento e CLI.

## 5. Instruções de Operação para o Usuário e Agentes

Todos os comandos devem ser executados com caminhos absolutos conforme `AGENTS.md`:

### 1. Inspecionar Capacidade de Slots, Filas e Status de Orçamentos
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py status
```

### 2. Configurar Teto Orçamentário Mensal para um Projeto
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py set-budget --project atrium --limit 50
python C:\dev\DarkFac\core\portfolio\cli.py set-budget --project jarvis --limit 40
```

### 3. Simular e Consultar Roteamento Ótimo de Modelo para uma Tarefa
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py route-task --task-type research --project atrium
python C:\dev\DarkFac\core\portfolio\cli.py route-task --task-type web_research --project jarvis
python C:\dev\DarkFac\core\portfolio\cli.py route-task --task-type architecture --project darkfac
```

### 4. Registrar Gasto Manual ou de Execução em Nuvem
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py record-spend --project atrium --amount 5.25
```

### 5. Enfileirar Tarefa no Escalonador Ponderado
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py enqueue-job --job-id job-prd-01 --project atrium --kind light --priority 10
python C:\dev\DarkFac\core\portfolio\cli.py enqueue-job --job-id job-test-suite --project darkfac --kind heavy --priority 5
```

### 6. Despachar Próxima Tarefa da Fila
```powershell
python C:\dev\DarkFac\core\portfolio\cli.py dequeue-job
```
