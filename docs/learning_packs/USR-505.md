## T4 — Declaracao explicita, sem id canonico para modelo fora de active

A sonda offline deixa de tratar o id canonico como alegacao OpenRouter quando o modelo e `candidate` ou `deprecated` e nao tem `gateway_ids`. Toda declaracao explicita, em qualquer status, precisa existir no snapshot `.factory/config/openrouter_catalog.json` (coleta de 2026-11-10, 469 ids).

`gemini-3.1-pro`, `gpt-image-2`, `claude-3-7-sonnet` e `gemini-2.0-flash-001` perdem os wire ids que a sonda de 2026-11-10 nao achou (`google/gemini-3.1-pro`, `openai/gpt-image-2`, `anthropic/claude-3.7-sonnet`, `google/gemini-2.0-flash-001`). `deepseek/deepseek-r1`, `deepseek-coder` e `claude-fable-5-1` continuam sem `gateway_ids`; o id com barra de `deepseek/deepseek-r1` nao vira alegacao. A copia embarcada em `core/models/registry.py` repete as mesmas listas. Status, aliases, roles e `review_pairs` ficam como estavam. <!-- census: wire-id -->

`gateway_id()` segue a regra de nome: sem `gateway_ids`, devolve o id canonico. Isso nao e uma alegacao de que o id existe no OpenRouter.
