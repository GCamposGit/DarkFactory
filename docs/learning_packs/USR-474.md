# USR-474 — Revisão OpenRouter com contexto verificável

## Em linguagem simples

A revisão enviada ao OpenRouter precisa carregar os critérios do ticket, conteúdo relevante já sanitizado e um manifesto que permita conferir os hashes. O serviço não consegue ler arquivos da worktree por conta própria. Se faltar contexto, a revisão é recusada como `review_context_unavailable`; se a resposta for cortada, é recusada como `review_output_truncated`.

## Para quem opera a frota

Antes de executar recuperação, confira a CLI com `python -m core.line.fleet_dispatcher --help`. Passe os tickets em um único valor separado por vírgulas, por exemplo `--recovery-tickets "USR-1,USR-2"`. Argumentos posicionais separados são recusados antes do ciclo começar.

## Escopo desta entrega

Este learning pack registra a atualização documental do T4. Não declara recibos de gate, CI, merge ou deploy.
